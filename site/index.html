See the screen, then act on it.

ui_control fuzzy-matches text in the accessibility tree, falls back to OCR, scrolls to find off-screen targets and restores your position when it fails. Every tap is verified by comparing the screen before and after — locate, act and check in a single call.

  • Tap, long-press, type, keys, scroll, wait-for
  • Screenshots, on-device OCR with coordinates, screen recording
  • Foreground app and screen state as first-class signals

Your keys never leave the device.

API keys are encrypted with the Android Keystore; transcripts, memories and run records live in a local database. There is no app server and no analytics. Cleartext HTTP is allowed only for loopback, so local models work without weakening anything else.

  • Keystore AES-GCM for secrets, Room for data
  • Permissions on demand — tools explain the next step when one is missing
  • Per-call confirmation in Act mode; Chat keeps only its private memory tools
  • Biomimetic memory: a constant-size core, on-demand recall across every past conversation, associative and prospective priming, privacy holds and suppression so a fact you asked to forget cannot come back
  • Notes keep their version history, can be corrected in place, and a long-press erases one for good

Modes

From chat to full autonomy, in one chip.

Chat

Plain conversation. Only the private memory tools are advertised, so nothing on the device can run.

Chat+

Read-only research: notifications, files, web, weather. Writes are denied by the gate.

Act

Every tool call pops a confirmation with the exact arguments before it runs.

Max

Autonomous runs with budgets — 60 rounds, 160 calls, 60 minutes — persisted and stoppable.

FAQ

Questions, answered.

What is BetterAIChat2?

A local-first Android AI agent. It runs an agent loop on your phone and gives the model 57 real device tools — screen reading, UI automation, files, web, reminders and more. It's the successor rewrite of BetterAIChat, released under GPL-3.0. Its agent is Aviiya: a tender, composed presence rather than a tool — softness first, honest before comforting, never pretending to be human.

Which models can I use?

DeepSeek, OpenAI, Anthropic and Gemini natively, plus any OpenAI-compatible endpoint (Kimi, Qwen, GLM, MiniMax, Ollama, vLLM, LM Studio, gateways). Paste an API key and the provider is detected; the model list is fetched from the endpoint.

Is it really private? Where are my keys?

Keys are encrypted with the Android Keystore (AES-GCM) and stored on the device. Conversations, memories and run records live in a local database. There is no app server, no account and no analytics; cleartext HTTP is allowed only for loopback addresses.

How does the memory work?

It is biomimetic, and it lives outside the context window. A small core (about you / what's ongoing) stays always-on with a constant footprint; past conversations and notes are recalled on demand with keyword, time, speaker and entity cues. Recalled notes strengthen and fade more slowly, notes recalled together wire together (two hops of spreading activation), upcoming plans surface by time on their own, near-duplicates are reconsolidated instead of duplicated, a curator rehearses fading high-value notes and prunes what is never used, and consolidation runs when the app leaves the foreground — sleep-time replay, not mid-task. Notes carry their source (what you said vs. the model's inference vs. scraped text), every note can be pinned, edited or forgotten, and a forgotten fact leaves a suppression fingerprint so it cannot be silently relearned. Raw transcripts are never summarized away.

Do I need Shizuku or root?

No. Most tools — accessibility automation, screen capture, files, web, personal-assistant tasks — work without it. Shizuku only unlocks run_shell and deep app management, and it's optional.

Does it drain the battery?

Nothing lingers while idle. Long runs (Act / Max, scheduled tasks) hold a foreground service that can be stopped from the notification, and screen capture is owned by a foreground service only after you grant it.

What happens if a run is stopped mid-tool-call?

Stopping synthesizes "cancelled" tool results for interrupted calls and rewrites their status, so the transcript always satisfies the model's protocol. You can keep chatting or retry — the conversation never breaks.

Does it work without Google Play Services?

Yes. The app has no GMS dependency; OCR runs on-device with a bundled model, so it works on de-Googled devices and emulators.

How is this different from the original BetterAIChat?

It's an architecture rewrite: new package name, new signing key, new agent runtime, new UI. It installs side by side with the old app and shares no data. Later releases upgrade in place.

Is it free?

Yes — free software under GPL-3.0. You only pay your model provider for what you use, and API keys stay on your device. If you find it useful, star the repo or open an issue with feedback.
